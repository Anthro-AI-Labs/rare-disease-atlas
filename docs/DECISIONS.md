# Decisions & dead ends (one line each)
- Base graph = existing `pipeline/build_graph.py` kept as-is (paths already repo-root relative); `status`/schema validation added in export, not in the build script.
- `make data` fetches HPO `genes_to_disease.txt` (not `genes_to_phenotype`) because build_graph reads it.
- NCBI: omit `api_key` param when unset (empty value returns "API key invalid"); throttle 3 req/s no key, 10 with.
- ClinicalTrials.gov gene search is free text, so studies are labelled "mentions gene", not "studies disease".
- Python deps in `venv/`; Python 3.14 works with pinned-free requirements.
- ClinicalTrials.gov: of 198 gene-term hits (CDKL5 alone 118, mostly noise), only records naming the gene in title/conditions/keywords enter the graph; studies link to non-counterexample diseases of that gene.
- Edge `status` is assigned at export: computed → hypothesis (rule 3), curated/manual/llm → supported.
- Web reads graph.json at build time (SSG, `generateStaticParams`); Next 16 `params` is a Promise.
- `extract_mechanisms.py` exits with a notice (not error) when OpenAI env is unset so `make graph` still works.
- Dead end: moving the stub `web/` aside was blocked; scaffolded Next in scratchpad and copied in instead.
- Claim.disease_context is a per-gene enum (that gene's HPO disease names + "unspecified"); built dynamically; allowed list is in the LLM cache key. Disease pages show claims for that disease + gene-level "unspecified" only.
- Confidence for LLM claims: 0.8 span names gene & human; 0.7 names gene, non-human; 0.5 otherwise (172/561 are 0.5, labelled low-confidence in UI).
- Clustering: complete-graph Louvain replaced by kNN(k=3)+Louvain, 30-seed co-assignment stability. SCN2A BFIS3 still co-clusters with SCN2A DEE11 (freq 1.0, phenotype-only): both flagged "uncertain", not hidden.
- Model gpt-5.4-mini; 333 abstracts → 596 claims → 561 verified (35 span drops, 0 gene-mismatch); full rerun from cache 0.5s.
- data/curated/evidence_review.csv drafted by pipeline/make_review_sample.py (reviewer columns empty). All 20 are span_mentions_gene=false AND non-human (priority rule exhausted the pool).
- Phase 2: targeted PubMed queries (benign terms / DEE terms) added for SCN2A, SCN8A, KCNQ2 only (+~150 abstracts); disease-level evidence for SCN2A/SCN8A benign forms stays thin (1 directional claim each) — reported, not forced.
- Counterexample rule (lead correction): benign+severe may share variant_effect. Co-clustering is "same mechanism, different severity" only if both sides have >=3 directional disease-level claims with the same dominant effect; else "uncertain membership"; different clusters = "separated". Weights fixed a priori (0.6/0.4), never tuned to pass.
- Mechanism profile = pooled weighted Jaccard over variant_effect and molecular_function marginals. Dead end: joint effect×function key gave overlap ≤0.15 everywhere (function labels vary per abstract), changed AFTER seeing this and disclosed here.
- Gene-level "unspecified" claims are attributed to a disease only when the gene has exactly one disease in the slice (not SCN2A/SCN8A/KCNQ2). Not used for contradictions.
- Contradictions: reduced (LOF/DN) vs increased (GOF) claims for the same disease, each side >=2 PMIDs; sides with non-overlapping linked-phenotype tokens (Jaccard<0.2) => "mixed" finding. Heuristic: SCN2A DEE11 is flagged "contradicted" (2 LOF vs 4 GOF, phenotype strings overlap) though known biology is onset-dependent; needs expert review.
- Unclear variant_effect: confidence capped 0.4, excluded from profiles/similarity. Claim edge ids are now stable hashes (M+8 hex), not sequential; v1 review file keeps legacy ids and is joined by pmid+span.
- Review precision per tier uses ONLY the random v2 sample (v1 was a priority sample). UI shows "not yet reviewed" until verdicts (correct|partial|incorrect) are filled in.
- Gap engine is template-based (no LLM). Route "supported" needs a curated connection (same gene) + a lead; computed-only => "hypothesis".
- Phase 3 (lead): same-gene-only routes demoted to "hypothesis"; "supported" now needs a curated shared patient group or asset between two diseases (or fixture/real CSV rows). Until patient_groups.csv/assets.csv have rows no route can be supported.
- UI relabels status "contradicted" as "Conflicting evidence: expert review needed" (data status unchanged); both sides + PMIDs shown; onset/variant/system dependence stated as a hypothesis only. Benign SCN2A/SCN8A pairs shown as "insufficient disease-level evidence" (a finding).
- Search: static index (web/public/data/search.json, 314 entries) built at export: diseases + MONDO synonyms, genes, HPO symptoms (+synonyms, propagated to slice diseases), mechanisms, patient groups. Client-side scoring; no server.
- Explanations: gpt-5.4-mini, input = route edges only (≤~25), validator = ids in input + no PMID/NCT/OMIM/HP/MONDO outside input refs + ≥1 uncertainty + next_step cited; retry once with the errors, then template. First run: 12/12 passed first try. Prompt shared in web/lib/explain-prompt.json (Python + TS).
- /api/explain: pre-generated explanations returned from graph.json without OpenAI; live route only for new edge-id sets; 5 req/min/IP in-memory (best effort on serverless); 503 when OPENAI env missing. NOT setting OPENAI_* in Vercel without the owner's go-ahead.
- Network: lead authors (first 2 + last 2) from PubMed efetch; shared only if two different papers support two different genes (a multi-gene review is not an overlap; dead end: first version flagged review-paper authors). ORCID/affiliation (token Jaccard>=0.5) = confirmed, else "possible match" (status hypothesis). RePORTER PIs not added (time).
- Curated loader hardened for partial files: BOM, header case, blank rows, multi-gene cells (; , / |), non-http URLs blanked, unusable rows listed in meta.curated_skipped.
- UI v3: three depths on one page (Simple story / Detailed map + evidence counts / evidence drawer), stored on `<html data-depth>` before paint so static pages switch with CSS only.
- Answer sentence, next step, "why" lines, copy-message and print sheet are templates over graph.json counts (no LLM). Recipient is left blank when no curated group exists (0 rows today), never invented.
- Common names = shortest MONDO synonym of the form "<GENE>-related encephalopathy/epilepsy", "<GENE> encephalopathy/syndrome" or "<GENE> benign…"; else "<GENE>-related encephalopathy". OMIM name always shown second.
- Gene tooltip function = most frequent molecular_function among that gene's entailed (yes) claims; text is fixed per controlled-vocabulary value.
- Scene A draws a direction only with ≥2 entailed quotes for it (BFIS3/BFIS5 have 1 → neutral "?"); any mixed finding → neutral "?". Motion = transform/opacity only; reduced motion = static final frame; `?motion=force` for demo recording.
- Dead end: theme colour named `base` collided with Tailwind's `text-base` size (text turned background-coloured in 3 places); renamed to `canvas`.
- Map: d3-force settled synchronously (400 ticks, deterministic) so SSR and client agree; wide/narrow layouts differ in cluster anchors; same-gene mild/severe pairs with uncertain grouping drawn pink dotted.
- Language v3: prompt adds 8th-grade style rules; validator adds a style check (no 'graph/edge/node'); edge-citation checks unchanged. 12/12 passed first try. Measured Flesch-Kincaid grade 15.1 -> 11.5 (words/sentence 25.4 -> 19.4); 'graph' mentions 42 -> 0. A second prompt pass did not lower the grade further (disease names and gene terms dominate); reading level is not a hard rule to avoid template fallbacks.
- Verification protocol: curated CSVs gained verified/verified_by/verified_at (+ second_verdict/second_by in review v2). Only verified=yes counts as human-verified; unverified patient_groups/assets load as status=hypothesis ("Not yet verified", conf 0.4) and cannot create a supported route. Review precision uses verified=yes rows only; agreement (percent, Cohen's kappa) is reported when second_verdict exists. Migration kept existing human entries in evidence_review_v2 rows 1-12 untouched.
- docs/review_packet.md is generated by deterministic string matching (no LLM): keyword tags are aids, not judgements; it omits confidence, entailment and verdicts so reviewers are not primed.
- Final integration pass. Review protocol: both reviewers are people (verified_by Varduhi, second_by Amin); an AI assistant only helped enter results and draft notes (stated on /methods). Precision uses final_verdict per sampling-time confidence tier (tier parsed from the CSV claim text, so later demotions cannot move a row), always with n. Agreement = verdict vs second_verdict over all 24 rows (14 of 24, 58.3%, Cohen's kappa 0.322). verdict, second_verdict and final_verdict are never written by the pipeline.
- Demotion check: the 5 sampled rows whose claim was already "unclear" (rows 18, 20, 22, 23, 24) are excluded from precision: 1 correct, 4 partial, 0 incorrect.
- Human demotion (A4): final_verdict=incorrect -> variant_effect "unclear", confidence <= 0.4, flagged human_demoted: Mf2026d98 (row 17, GNAO1 gain-of-function claim). Partial rows keep their status and show the reviewers' reason (edge ids: M301d2222, M0d3df851, Mdff303ba, M1ae0c78c, M6d03ea65, M04bcaa04, Mb09c7c53, Mddba61b7, M64fc6676, Mf978aa61, M0a8335dc).
- Review packet bug: the packet showed the original extracted effect for demoted rows; it now renders the CURRENT claim parsed from the CSV claim column and a test asserts packet claim == CSV claim.
- Recommendation rule (C1): only own-gene patient groups are ever recommended ("contact ..."). Groups of other genes appear only as "Related community (different gene: X)", never across opposite dominant effects (reduced vs increased function, needs >= 3 directional claims each), and the Copy-message To: line is never pre-filled (interpretation: a recipient from another gene must be chosen by the sender). SCN1A (loss of function) no longer gets SCN8A (gain of function) groups; with no own group it says "No patient group on file for SCN1A yet" + how to help.
- Shares-a-study (C2): assets with the same identifier on two genes link their non-benign diseases (edge shares_study_with). Supported only when the asset rows of BOTH genes are verified=yes, otherwise "pending verification" (status hypothesis, pending_verification=true). Assets are now one node per identifier. 6 links today (STARR, Simons Searchlight x3 gene pairs, FENDEEP, EMBOLD), all pending because assets.csv has verified=no everywhere.
- Patient groups serve every disease of their gene, benign forms included (C3). A group shared by two diseases of the SAME gene is not a cross-gene route (dead end: first version marked those routes supported).
- Route segments (D): own community / link / related community / shared asset, each supported | pending verification | hypothesis | not on file; overall = weakest part, always shown with the four. A phenotype-only route has no shared asset, so it reads "Route incomplete" (grey) however good the communities are. route_status kept for map colours (supported / hypothesis / none).
- 10x page: text moved verbatim to web/content/10x.md; the page adds links, a fraction layout for the formula and Measured / Sourced / Team-estimate labels chosen by pattern matching on each statement (no wording changed).
- Copy-message To: (final fix): pre-fill only a VERIFIED group of the gene the message is about: the related disease's own-gene group when the link is "shares a study" and the dominant effects are not opposite (STXBP1 -> SYNGAP1 via STARR -> CURE SYNGAP1), otherwise the page disease's own-gene group; else a placeholder. Never an opposite-gene or unverified group. Known oddity: for a non-study link the own-gene fallback addresses the sender's own community (e.g. STXBP1 Foundation about GNAO1); kept as instructed.
- Explanations: deterministic post-processing (pipeline/explain.py, mirrored in web/lib/explain.ts for the live route) drops any uncertainty sentence about (missing) "treatment" results and appends once: "This atlas does not track treatments. Ask your care team about current treatment options." Edge-citation validation unchanged; 8 of 12 explanations were affected.
- Checklists moved to docs/verification/. Verified-assets simulation (copy of assets.csv with STARR, EMBOLD, FENDEEP, Simons verified): STXBP1, SYNGAP1, SCN2A, SCN8A become fully supported; real confirmation waits for Varduhi's updated assets.csv.
